# 12 手机端控制计划

本文档记录 OpenRD 手机端控制的产品和技术计划。当前结论是：手机端先做 Web/PWA 驾驶界面，复用现有公网控制链路，不先引入新的车端通信链路或原生 App。

## 目标

- 让手机浏览器可以直接打开 OpenRD 控制台并安全控车；
- 复用现有 `openrd-control-service -> RK3588 control agent -> ESP32` 控制链路；
- 为触屏驾驶单独设计移动端 UI，而不是压缩桌面端布局；
- 保持低速、可中断、可观测，优先保证安全和可控性。

## 非目标

- 暂不做手机直连 ESP32 的蓝牙或局域网控制；
- 暂不做原生 Android/iOS App，除非后续 PWA 无法满足手感或系统能力需求；
- 暂不重构云端 control service、RK3588 control agent、ESP32 控制协议；
- 暂不把视频体验作为第一优先级，手机端先保证驾驶控制可靠。

## 当前推荐架构

```text
手机浏览器 / PWA
  -> 云端 openrd-control-service
  -> RK3588 openrd-control-agent
  -> ESP32 OpenRD-Driver
  -> 小车底盘
```

手机端只是新的输入界面。控制命令仍然走现有公网链路：

```text
POST /api/vehicles/openrd-001/drive/command
```

状态仍然读取：

```text
GET /api/vehicles/openrd-001/drive/status
```

## 设计原则

- **控制优先**：急停、松手停、连接状态优先于视频和装饰信息；
- **低速默认**：手机端默认速度上限建议为 `200` 或 `300`，高档需要显式切换；
- **单手/双手可用**：横屏优先，左右拇指自然覆盖转向、油门、停止和急停；
- **状态醒目**：云端在线、RK 在线、drive state、RTT、命令龄、agent 上报龄必须明显；
- **输入固定频率发送**：触摸事件可以高频采样，但网络命令按 10-20Hz 节流发送；
- **失焦即停**：页面隐藏、锁屏、切后台、触摸取消、网络异常都应立即发 stop；
- **不复用桌面布局硬压缩**：手机端应有独立驾驶模式和控件尺寸。

## MVP 范围

第一版只做最小可用的手机驾驶模式：

- 横屏移动端布局；
- 左侧触控摇杆或二维触控区，输出 `steering` 和 `throttle`；
- 右侧固定 `STOP` 和 `ESTOP`；
- 速度上限分档：低/中/高，默认低档；
- 云端连接按钮和连接状态；
- 控制链路延迟显示：控制 RTT、状态 RTT、命令龄、agent 上报龄；
- 页面失焦、触摸结束、触摸取消时自动发送 stop；
- 保留视频入口，但不让视频占用急停和核心控制区域。

## UI 草案

横屏建议布局：

```text
+------------------------------------------------------+
| 状态栏：云端/RK/ESP32/RTT/速度档/电量                  |
+------------------------------+-----------------------+
|                              |  STOP                 |
|        触控驾驶区             |                       |
|   steering / throttle        |  ESTOP                |
|                              |                       |
|                              |  速度档  低 中 高      |
+------------------------------+-----------------------+
| 可折叠调试区：命令龄、agent 上报龄、事件日志、视频小窗   |
+------------------------------------------------------+
```

纵屏可以作为只读/调试模式，不建议作为第一版主要驾驶模式。

## 安全策略

手机端必须实现以下保护：

- 手指离开触控区立即发送 `drive.stop` 或零输入；
- `visibilitychange`、`pagehide`、`blur`、`beforeunload` 触发 stop；
- 连续状态请求失败超过阈值后，UI 进入不可控状态并发送 stop；
- 急停按钮始终可见，且不被视频或调试区遮挡；
- 速度档切换必须明确显示当前上限；
- 默认不允许页面加载后自动进入可驾驶状态，需要用户主动连接。

后端和车端已有命令 TTL/agent 状态保护，手机端仍要做前端侧快速 stop，减少体感风险。

## 实现计划

### 阶段 1：移动端驾驶模式

- 在 Flutter 前端增加移动端布局判断；
- 新增 `MobileDriveView` 或等价组件；
- 复用现有 cloud drive client；
- 保持桌面端布局不变。

### 阶段 2：触控输入与安全停

- 实现触控区归一化输出；
- 按固定频率发送 `drive.command`；
- 加入 touch end/cancel、页面失焦、断连 stop；
- 默认速度上限设为低档。

### 阶段 3：状态和延迟可视化

- 在手机状态栏展示 `drive_agent_online`、`drive_state`；
- 展示控制 RTT、状态 RTT、命令龄、agent 上报龄；
- 增加事件日志，记录连接、停止、急停、断连。

### 阶段 4：实车低速验证

- 使用低速档验证前进、后退、左转、右转、停止；
- 验证松手停、切后台停、断网停；
- 记录手机触控手感、RTT 和控制稳定性；
- 根据实车反馈调整触控区曲线和速度档位。

### 阶段 5：PWA 化

- 增加 Web App Manifest；
- 设置移动端图标、名称、启动模式；
- 验证手机浏览器“添加到主屏幕”；
- 决定是否部署到云端静态站点，形成固定公网入口。

## 验收标准

- 手机浏览器可打开控制台并连接云端；
- 低速档下可完成前进、后退、左转、右转、停止；
- 手指离开触控区后车辆立即停止；
- 页面切后台或锁屏后车辆停止；
- 急停按钮始终可点击；
- 控制状态和延迟指标持续刷新；
- 不影响现有桌面端控制台。

## 后续可选方向

- 打包 Android APK，用于沉浸式全屏和更稳定的横屏控制；
- 接入手机陀螺仪作为可选转向输入；
- 支持 WebHID/Gamepad，连接手机外设手柄；
- 做手机端视频小窗或全屏视频驾驶模式；
- 加入用户认证和控制权限，避免公网控制台被未授权访问。

## 当前建议

下一步应先实现 **阶段 1 + 阶段 2**：手机横屏驾驶模式、触控输入、松手停、失焦停和低速默认。只要这部分稳定，后续 PWA、视频小窗和原生 App 都可以自然演进。
